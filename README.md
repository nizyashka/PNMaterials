# PN-Materials

Система учёта оборота материалов: справочники материалов и их групп, заявки
на закупку с отслеживанием статусов и отчёт по заявкам.

Приложение состоит из двух частей — серверного веб-API с базой данных и
десктопного клиента. Клиент работает исключительно через HTTP-API и не
обращается к базе данных напрямую, поэтому сервер может быть развёрнут на
отдельной машине.

## Возможности

### Справочники

- **Единицы измерения** — предустановленный список, недоступный для изменения
  пользователем.
- **Группы материалов** — создание, просмотр, изменение и удаление. Группу
  нельзя удалить, пока в ней есть материалы.
- **Материалы** — создание, просмотр, изменение и удаление. Код материала
  (восемь цифр) присваивается системой при сохранении и в дальнейшем не
  меняется. Материал нельзя удалить, если он используется в заявках.

### Заявки на закупку

- Номер заявки (десять цифр) и дата создания присваиваются системой.
- Дата поставки по умолчанию — месяц от текущей даты; прошедшая дата не
  принимается.
- Заявка содержит произвольное количество позиций. В позиции выбирается код
  материала, наименование и единица измерения подставляются автоматически.
- Заявку можно создать из общего списка или из карточки материала — во втором
  случае материал сразу попадает в первую позицию.
- Статусы заявки: создана (СЗДН), запущена в работу (ВРБТ), закупка
  осуществлена (ВПЛН), удалена (УДЛН). Переходы между статусами ограничены
  правилами; доступные действия сервер сообщает клиенту при каждом запросе
  заявки.

### Отчёт по заявкам

Выборка по номерам заявок, кодам материалов, наименованию материала,
диапазону дат поставки и статусам. Коды перечисляются через запятую, в
наименовании неизвестная часть обозначается звёздочкой, для статусов доступно
условие «не равно». Результат содержит номер заявки, требуемую дату поставки и
статус.

## Требования

- .NET SDK 10.0
- Microsoft SQL Server (подойдёт любая редакция, включая Express и Developer)
- Visual Studio 2022 или новее — необязательно, проект собирается и запускается
  из командной строки

## Запуск

### 1. Проверить строку подключения

Файл `PNMaterialsAPI/appsettings.json`:

    "ConnectionStrings": {
      "DefaultConnection": "Server=localhost;Database=PNMaterials;Trusted_Connection=True;TrustServerCertificate=True"
    }

Значение по умолчанию рассчитано на экземпляр SQL Server по умолчанию с
проверкой подлинности Windows. Для именованного экземпляра нужно указать его
имя, например для SQL Server Express:

    Server=localhost\SQLEXPRESS;Database=PNMaterials;Trusted_Connection=True;TrustServerCertificate=True

Для проверки подлинности SQL Server:

    Server=localhost;Database=PNMaterials;User Id=sa;Password=<пароль>;TrustServerCertificate=True

Создавать базу данных вручную не требуется: при первом запуске API применит
миграции и создаст её со всеми таблицами и справочником единиц измерения.

### 2. Запустить сервер

    dotnet run --project PNMaterialsAPI

API поднимется на `https://localhost:7073`. В режиме разработки по адресу
`https://localhost:7073/swagger` доступна интерактивная документация, через
которую можно проверить работу методов без клиента.

### 3. Запустить клиент

В отдельном окне терминала:

    dotnet run --project PNMaterialsClient/PNMaterialsClient -f net10.0-desktop

В Visual Studio удобнее настроить одновременный запуск: правой кнопкой по
решению, «Configure Startup Projects», «Multiple startup projects», для
`PNMaterialsAPI` и `PNMaterialsClient` выбрать «Start».

## Конфигурация клиента

Адрес сервера задаётся в файле `appsettings.json` рядом с исполняемым файлом
клиента:

    {
      "ApiBaseAddress": "https://localhost:7073/"
    }

Файл читается при запуске. Если он отсутствует или повреждён, используется
адрес по умолчанию, совпадающий с приведённым выше.

## Структура решения

| Проект | Назначение |
| --- | --- |
| `PNMaterialsDomain` | Сущности предметной области и правила, не зависящие от способа хранения: формат кодов, таблица переходов статусов, разбор поисковой маски |
| `PNMaterialsInfrastructure` | Работа с базой данных: контекст Entity Framework, конфигурации сущностей, миграции, генераторы кодов |
| `PNMaterialsContracts` | Объекты передачи данных, общие для сервера и клиента |
| `PNMaterialsAPI` | Веб-API на ASP.NET Core |
| `PNMaterialsClient` | Десктопный клиент на Uno Platform |
| `PNMaterialsTests` | Модульные тесты |

Зависимости между проектами направлены так, чтобы клиент не мог обратиться к
базе данных в обход API:

    PNMaterialsAPI ──> PNMaterialsInfrastructure ──> PNMaterialsDomain
          │                        │
          └──> PNMaterialsContracts <┘
                       ▲
                       │
               PNMaterialsClient

Клиент ссылается только на `PNMaterialsContracts`, поэтому классы Entity
Framework для него недоступны на уровне компиляции.

## Методы API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/units` | Справочник единиц измерения |
| GET | `/api/materialgroups` | Список групп материалов |
| GET | `/api/materialgroups/{id}` | Группа материалов |
| POST | `/api/materialgroups` | Создание группы |
| PUT | `/api/materialgroups/{id}` | Изменение группы |
| DELETE | `/api/materialgroups/{id}` | Удаление группы |
| GET | `/api/materials` | Список материалов |
| GET | `/api/materials/{id}` | Материал |
| POST | `/api/materials` | Создание материала |
| PUT | `/api/materials/{id}` | Изменение материала |
| DELETE | `/api/materials/{id}` | Удаление материала |
| GET | `/api/purchaserequests` | Список заявок |
| GET | `/api/purchaserequests/{id}` | Заявка с позициями |
| GET | `/api/purchaserequests/statuses` | Список статусов заявки |
| POST | `/api/purchaserequests` | Создание заявки |
| PUT | `/api/purchaserequests/{id}` | Изменение заявки |
| POST | `/api/purchaserequests/{id}/status` | Смена статуса заявки |
| POST | `/api/reports/purchase-requests` | Отчёт по заявкам |

Отчёт запрашивается методом POST, потому что условия выборки представляют собой
структуру со списками значений и диапазоном дат — передавать её в теле запроса
удобнее, чем в строке адреса.

## Тесты

    dotnet test

Тестами покрыта логика, не зависящая от базы данных и интерфейса: формирование
кодов материалов и номеров заявок, правила переходов между статусами заявки и
преобразование поисковой маски в шаблон запроса.

## Сборка под Linux

Клиент использует отрисовку Skia и собирается для Linux из того же исходного
кода:

    dotnet publish PNMaterialsClient/PNMaterialsClient -c Release -f net10.0-desktop -r linux-x64

Сервер собирается аналогично:

    dotnet publish PNMaterialsAPI -c Release -r linux-x64

Для запуска клиента в Linux в системе должны присутствовать графическое
окружение и библиотека `fontconfig`.

## Решения по реализации

**Коды материалов и номера заявок** выдаются последовательностями SQL Server, а
не вычисляются как «максимальное значение плюс один». Последовательность
атомарна и гарантирует уникальность при одновременном создании записей
несколькими пользователями. Кэширование последовательностей отключено: иначе
после перезапуска SQL Server неиспользованные значения теряются и в нумерации
появляются заметные разрывы.

**Удаление заявки** реализовано как перевод в статус «удалена», а не как
удаление строки. Заявка остаётся доступной для отчёта, а из статуса «удалена»
её можно вернуть в работу.

**Правила переходов между статусами** описаны только на сервере. При запросе
заявки API возвращает перечень статусов, в которые она может перейти, и клиент
строит кнопки по этому перечню, не дублируя логику.

**Миграции применяются при запуске API.** Это упрощает развёртывание и
знакомство с проектом. В промышленной эксплуатации миграции обычно выполняются
отдельным шагом, чтобы несколько экземпляров приложения не начинали изменять
схему одновременно.

**Ограничения на данные проверяются дважды** — в объектах передачи данных на
входе в API и на уровне схемы базы. Первая проверка возвращает пользователю
понятное сообщение, вторая защищает данные от ошибок в коде.

**Перечисление нескольких значений в отчёте** выполняется в одном поле ввода
через запятую, точку с запятой или пробел. Это позволяет вставить готовый
список из буфера обмена и не требует отдельного интерфейса для добавления
значений по одному.

**Редактирование заявки** доступно в любом статусе. Ограничения на изменение
выполненных или удалённых заявок не задавались.
